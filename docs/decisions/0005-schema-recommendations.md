# 0005 — Schema recommendations DB-REC-01 to 12 confirmed; deferrable positions by hand-written SQL
- **ID:** PLAN-DEC-01 (closes DB-REC-01 to DB-REC-12 and DB-OQ-15)
- **Date:** 2026-10-16
- **Status:** decided
- **Decision:** All twelve recommendations in Schema §12 are confirmed as written: DB-REC-01 `lesson_progress.furthest_stage`; DB-REC-02 `attempts.context`, `attempts.lesson_id`, `attempts.stage`; DB-REC-03 `attempts.given_answer` as `jsonb`; DB-REC-04 `example` as a block kind with `lesson_blocks.example_id`; DB-REC-05 `lesson_status` planned, published, retired and `lessons.revision`; DB-REC-06 `cefr_level` as an enum; DB-REC-07 `position` on course_parts, `normal` section weight, `lesson_objectives.role` reusing the four block roles; DB-REC-08 surrogate `id` keys on exercise_targets and the learner tables, composite keys on link tables; DB-REC-09 partial unique indexes for audio identity and one-target tables; DB-REC-10 delete rules DB-DEL-03 to 09, including audio deleted with its owner; DB-REC-11 checks DB-CK-02, 04, 05, 06, 09, 10, 11; DB-REC-12 the enum value spellings, the closed `register` list and the `production_method` names. For DB-OQ-15: drizzle-kit does not generate deferrable constraints, so the position unique constraints are made `DEFERRABLE INITIALLY DEFERRED` in a hand-written migration (`drizzle-kit generate --custom`). Unique constraints on `code` stay non-deferrable so they can be upsert conflict targets.
- **Reason:** The owner had approved the recommendations in principle; they fit the rest of the schema and cost nothing to adopt before data exists. DB-OQ-15 was checked against drizzle-orm 0.45.4 and drizzle-kit 0.31.11 (latest on 2026-10-16): the pg-core constraint builders have no `deferrable` option and the kit never emits `DEFERRABLE` for constraints.
- **Affects:** Schema §8, §9 (position uniqueness, DB-OQ-15), §12, §15; Plan §5 Phase 2 (tasks 2a.2, 2a.3, 2b.1)
